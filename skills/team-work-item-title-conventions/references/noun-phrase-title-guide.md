# 이슈·PR·커밋 명사형 제목 가이드

## 기본 규칙

제목은 변경의 목적 또는 결과를 나타내는 짧은 명사형 구로 작성한다. `추가한다`, `수정한다`, `구현한다`, `적용한다`, `개선한다`처럼 문장을 끝내는 동사 표현과 `추가해라` 같은 명령형은 사용하지 않는다.

- 이슈: `[BE][FEATURE] 사용자 프로필 조회 API 제공`
- 이슈: `[FE][TASK] 결제 완료 흐름 모바일 E2E 검증`
- PR: `feat: 사용자 프로필 조회 API 제공`
- 커밋: `docs: 기능·테스크 이슈 가이드 보완`

제목의 `추가`, `제공`, `표시`, `개선`, `검증`, `문서화`, `보완`, `분리`, `정리`는 변경 결과를 가리키는 명사형으로 사용한다. 동사 어미가 붙지 않은지 확인한다.

| 피해야 할 제목 | 권장 제목 |
| --- | --- |
| `feat: 사용자 프로필 API를 추가한다` | `feat: 사용자 프로필 조회 API 추가` |
| `[BE][FEATURE] 로그인 API를 구현한다` | `[BE][FEATURE] 로그인 API 제공` |
| `[FE][TASK] 오류 메시지를 표시한다` | `[FE][TASK] 오류 메시지 표시` |
| `fix: 결제 오류를 수정해라` | `fix: 결제 승인 오류 수정` |

## 형식별 적용

### GitHub 이슈

- 기능 부모: `[BE][FEATURE] 결과`, `[FE][FEATURE] 결과`
- 하위 테스크: `[BE][TASK] 결과`, `[FE][TASK] 결과`
- 장애·버그 이슈: `[BUG] 현상 또는 영향`

제목에는 해결 방법의 구현 세부보다 사용자 또는 시스템 결과를 쓴다. 단, 독립 테스트 테스크는 검증 대상과 검증 종류를 쓴다.

### Pull Request와 커밋

`<type>[scope][!]: <명사형 결과>` 형식을 사용한다. 기존의 type, scope, `!`, 본문, 꼬리말 규칙은 그대로 적용한다.

- `feat(auth): 소셜 로그인 기능 추가`
- `fix(payment): 결제 승인 오류 수정`
- `docs: 기능·테스크 이슈 가이드 보완`
- `refactor(user): 사용자 조회 흐름 정리`

영문 제목도 명령형 동사 대신 결과 중심 명사구를 사용한다. 기술 식별자나 프로젝트가 정한 고유 명칭은 번역하지 않는다.

## 검토 순서

1. 제목 끝이 `한다`, `했다`, `해라`, `하세요` 등 동사 문장형·명령형이 아닌지 확인한다.
2. 제목만 읽고 변경 결과 또는 이슈의 목적을 이해할 수 있는지 확인한다.
3. 이슈는 영역·유형 접두사, PR·커밋은 type·scope 형식을 유지하는지 확인한다.
4. 제목이 아닌 본문에 변경 이유, 구현 방법, 검증 결과를 둔다.
