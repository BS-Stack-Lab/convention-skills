# 개발 전 작업 이슈 작성

기능, 개선, 리팩터링을 개발하기 전에 부모 이슈를 작성·수정·검토할 때 사용한다. 이미 발생한 장애·버그·사용자 문의 대응 이슈에는 `team-incident-issue-authoring`을 사용한다.

작성 전에 [개발 전 작업 이슈 원문 가이드](references/development-work-issue-guide.md) 전체를 읽는다. 이 파일은 팀이 제공한 내용을 원문 그대로 보관한 기준 문서다.

- 구현 방법보다 사용자 또는 비즈니스 문제와 기대 결과를 먼저 작성한다.
- 알 수 없는 정보는 추정해 채우지 말고 `결정 필요`와 담당자 또는 논의 채널을 남긴다.
- 부모 이슈에는 목적·범위·완료 조건을, 독립 배정 가능한 API·화면·테스트·문서 작업은 하위 이슈로 나눈다.
- 완료 조건에는 정상 흐름, 예외 흐름, 테스트 또는 리뷰 기준을 포함한다.
- GitHub 이슈 생성·수정처럼 외부 상태를 바꾸는 행동은 사용자가 명시적으로 요청한 경우에만 수행한다.

작성 결과는 원문의 복사 템플릿을 기준으로 하되, 사용자가 제공하지 않은 이슈 번호·담당자·일정·링크는 만들지 않는다.
