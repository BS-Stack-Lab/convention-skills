- 작업 목적:
- 변경이 필요한 이유:

## 변경 요약

- 변경 전:
- 변경 후:
- 핵심 설계 또는 구현 방식:

## 영향 범위

- 사용자 기능 또는 화면:
- API / DB / 배치:
- 외부 시스템 또는 인프라:
- 성능 / 보안 / 개인정보:
- 장애 발생 시 영향:
- 변경 없음:

## 리뷰어가 꼭 봐야 할 부분

> 판단, 설계 의도, 트레이드오프가 있는 부분만 작성합니다.

- `파일명:라인`: 검토가 필요한 이유
- 고려한 대안:

- 실행 명령어:

- 테스트 환경:
- 사전 조건:

- 실제 결과:

- 배포 전 확인 사항:
- 배포 순서:

> UI·사용자 흐름·CLI 출력 변경 시 첨부합니다.

| 변경 전 | 변경 후 |

|      |      |

## 체크리스트

- [ ] 설계 문서 또는 관련 논의를 연결했습니다.
- [ ] 영향 범위와 장애 가능성을 검토했습니다.
- [ ] 필요한 자동화·통합·수동 테스트를 수행했습니다.
- [ ] 배포 및 롤백 방법을 확인했습니다.
- [ ] UI 변경 시 스크린샷 또는 데모를 첨부했습니다.
- [ ] 민감 정보, 디버그 코드, 불필요한 파일이 포함되지 않았습니다.

고위험 PR은 변경의 의사결정 과정, 최악의 장애 영향, 배포 순서, 롤백 기준을 구체적으로 남긴다. 외부 시스템을 Mock 했는지와 실제 연동 환경을 사용했는지를 분명히 작성한다.
