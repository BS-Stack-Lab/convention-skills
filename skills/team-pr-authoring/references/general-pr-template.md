# 일반 PR 템플릿

```markdown
## 작업 내용 / 이슈
- 관련 이슈: Closes #
- 작업 목적:

## 변경 요약
- 변경 전:
- 변경 후:

## 영향 범위
- 영향받는 기능 또는 화면:
- API / DB / 외부 연동:
- 영향 없음:

## 리뷰어가 꼭 봐야 할 부분 (선택)
> 설계 판단, 예외 처리, 호환성 등 집중 검토가 필요한 부분이 있을 때 작성합니다.
> 없으면 `해당 없음`으로 작성합니다.

- `파일명:라인`:
- 검토가 필요한 이유:
- 고려한 대안 또는 질문:

## 테스트 방법
### 자동화 테스트
- 실행 명령어:
- 결과:

### 수동 테스트
1.
2.
3.

- 기대 결과:
- 실제 결과:

## 스크린샷 또는 데모
> UI·사용자 흐름·CLI 출력 변경 시 첨부합니다.
> 변경이 없으면 `해당 없음`으로 작성합니다.

| 변경 전 | 변경 후 |
| --- | --- |
|  |  |

## 체크리스트
- [ ] 하나의 목적에 집중된 PR입니다.
- [ ] 필요한 테스트를 추가·수정하고 실행했습니다.
- [ ] UI 변경 시 스크린샷 또는 데모를 첨부했습니다.
- [ ] 민감 정보, 디버그 코드, 불필요한 파일이 포함되지 않았습니다.
```

작성 시 관련 이슈는 `Closes #번호`로 연결한다. 이슈가 없으면 해결할 사용자·운영상 문제를 한두 문장으로 쓴다. 자동화 테스트에는 실행 명령어와 결과를, 수동 테스트에는 사전 조건·절차·기대 결과·실제 결과를 남긴다.
