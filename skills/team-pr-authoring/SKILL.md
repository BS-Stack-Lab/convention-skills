# PR 작성 규칙

PR 본문을 작성하거나 수정하거나 리뷰할 때 사용한다. 사용자가 PR, Pull Request, PR 설명, PR 템플릿, PR 리뷰를 언급하면 이 스킬을 먼저 적용한다. 구현 목록이 아니라 변경 목적, 영향 범위, 검증 결과를 중심으로 작성한다.

## 템플릿 선택

다음 중 하나라도 해당하면 고위험 PR이다.

- 결제, 인증, 권한 변경
- DB 스키마 변경 또는 데이터 마이그레이션
- 외부 시스템, 메시지 큐, 캐시, 인프라 연동
- 대규모 리팩터링
- 성능, 보안, 개인정보 영향
- 장애 또는 데이터 정합성 위험

고위험 PR이면 [고위험 PR 작성 가이드](references/high-risk-pr-guide.md)를 먼저 읽고, [고위험 템플릿](references/high-risk-pr-template.md)을 사용한다. 그 외에는 [일반 PR 작성 가이드](references/general-pr-guide.md)를 먼저 읽고, [일반 템플릿](references/general-pr-template.md)을 사용한다.

## 공통 원칙

- PR 제목은 `team-work-item-title-conventions`의 명사형 제목 규칙을 적용한다.
- 실제로 실행하지 않은 테스트를 통과했다고 작성하지 않는다.
- 영향 없음은 검토한 영역과 근거를 함께 작성한다.
- UI, 사용자 흐름, CLI 출력이 바뀌면 변경 전후 증빙을 첨부하거나 해당 없음을 명시한다.
- 스크린샷, 로그, 데모에는 개인정보, 토큰, 주문번호, 전화번호, 내부 URL 등 민감 정보를 남기지 않는다.
- 리뷰어에게는 파일 위치, 판단할 내용, 선택 이유와 대안을 구체적으로 제시한다. `전체 확인 부탁드립니다`처럼 포괄적으로 요청하지 않는다.
